2. COLOUR SCHEME  (src/theme.ts)
================================================================================
Dark violet/indigo palette. Two accents only: violet (primary) and
periwinkle (secondary, used for "the payoff" / final states).

BACKGROUNDS
  bg          #0E0820   page background
  bgAlt       #0B0619   alternating / darker band
  card        #140E24   card surface
  cardAlt     #171029   raised card surface
  inner       #0F0A1E   inset panel inside a card (mock UI panels)

TEXT
  text        #EFEAF9   primary body + headings
  textSoft    #C9C3DC   secondary text
  muted       #9B95B4   body copy in cards
  faint       #7E7898   labels, meta, captions
  faintest    #7E7898   (same value; kept for semantic naming)

ACCENTS
  violet        #7C4DCC   primary — buttons, dots, rules, tag numbers
  violetLight   #A87BE8   section eyebrow labels, FAQ +/-, stat numbers
  violetBright  #AE6BEC   hover/active accent, hex grid lines
  peri          #7E9AF5   secondary accent — final step, outbound tag,
                          "instantly" pulse, third stat
  line          rgba(124,77,204,0.18)   default hairline border

BUTTON HOVER
  #8F5CE0  (violet buttons lighten on hover)

CARD HOVER
  border  -> rgba(174,107,236,0.5)
  transform -> translateY(-4px)
  background -> #181031

TEXTURE
  hexGrid — two crossed repeating-linear-gradients at +/-60deg,
  rgba(174,107,236,0.04), 64px pitch. Used as a faint background weave.

DEMO APPS use their own light/neutral palettes (they represent a client's
product, not the Seqnc brand). The only brand tie-in is the "Back to Seqnc"
link in each demo header.

3. TYPOGRAPHY
================================================================================
ONE TYPEFACE, TWO ROLES — Manrope.
display  'Manrope', sans-serif  ·  weight 800   wordmark, headlines, stat
                                                numbers, card titles, prices
body     'Manrope', sans-serif  ·  weight 500   all body copy, set globally on
                                                <body> in index.html
mono     'Azeret Mono', monospace              eyebrow labels, badges, tags
                                                (retained as a system accent)
Tracking: tight on display (-0.02em to -0.035em), neutral on body.
Loaded from Google Fonts in index.html: Manrope 500/600/700/800 + Azeret Mono
400/500. Plus Jakarta Sans and DM Sans have been removed entirely.

SHARED TYPE STYLES (theme.ts)
  label   mono · 11px · letter-spacing 0.16em · UPPERCASE · violetLight
          -> every section eyebrow ("The problem", "Live demos", ...)
  h2      display · clamp(30px, 3.6vw, 46px) · line-height 1.05
          letter-spacing -0.03em · weight 700 · text-wrap balance
          -> every section headline
  card title   display · 24px · -0.02em · 700
  card body    16px · 1.6 · muted
  chip/badge   mono · 11px · 0.12em–0.16em · UPPERCASE
  numerals     font-variant-numeric: tabular-nums everywhere numbers align

4. PAGE STRUCTURE — HOMEPAGE
================================================================================
Order is set in src/pages/Index.tsx. A skip-to-content link sits above the
navbar for keyboard users. Sections reveal on scroll via <Reveal> (opacity +
translateY(26px), staggered with a delay prop).

  1. Navbar        Logo, anchor nav (Problem / Systems / How It Works /
                   Pricing), EN-FR toggle, "Free review" CTA.
  2. Hero          Eyebrow "The TimeBack Method™" -> headline in two parts
                   (bright line + muted line) -> body -> CTA + note.
                   Right side: "Where the week goes" leak chart — 3 rows of
                   task + hours, with an illustrative-data footnote.
  3. WhoStrip      Thin horizontal band. Eyebrow + one-line statement +
                   4 audience chips, laid out flex / space-between.
  4. Problem       Eyebrow, headline, body, 3 pain bullets, then a 3-up
                   benchmark stat row (animated counters, third stat in peri)
                   with a research disclaimer underneath.
  5. Systems       "Three Systems" — 3-column card grid. Each card:
                   number tag + system tag, title, body, a small diagram,
                   then 3 dash-bulleted outcomes.
                   01 Inbound   — 3 channel chips -> arrow -> reply row with
                                  pulsing "Instantly" badge
                   02 Operations— 4-step vertical timeline with badges
                   03 Outbound  — 4-row sequence table (day / message / state)
  6. CaseStudy     Divos Detailing. Before/After split panels, 3 capability
                   chips, live link, and a dashed "second case study in
                   progress" note with a pulsing dot.
  7. Demos         3-column grid, one card per demo. Each card: number tag,
                   title, body, an animated mock panel, then a violet
                   "Try me" button + a mono note. All three now link out to
                   the live static demos in /public/demo/.
                   01 -> /demo/inbound/    02 -> /demo/operations/
                   03 -> /demo/outbound/
  8. Process       "The TimeBack Method, start to finish" — 4 numbered steps
                   on a connecting line. Hovered step brightens; the final
                   step uses peri instead of violet.
  9. Pricing       Eyebrow, headline, body explaining why no price list, then
                   3 stacked explainer items (setup + retainer, cancel any
                   time, 90-day guarantee) and a CTA.
 10. Faq           8 accordion items. Grid-template-rows 1fr/0fr transition,
                   mono +/- indicator in violetLight.
 11. ClosingCta    Final push: headline, body, CTA, reassurance note.
 12. Footer        Tagline, Privacy Policy, Terms & Conditions links.

LEGAL PAGES
  /privacy-policy and /terms use LegalPage.tsx: max-width 900px, back-to-home
  link with a short violet rule, "Last updated" line, then headed sections of
  paragraphs and lists. Copy lives in en.ts/fr.ts under legal.privacy and
  legal.terms.

ALL CTAs point to: https://calendly.com/seqnc/free-review  (theme.ts CALENDLY)

6. LIVE DEMOS
================================================================================
Each demo is a standalone static app in public/demo/. No build step, no
framework — plain HTML + CSS + vanilla JS, so they ship as-is and are served
directly by the host. Every demo header carries a "Back to Seqnc" link to
/#demos.

01 INBOUND — public/demo/inbound/
   Tab title: Job Estimator - Inbound Demo
   Files: index.html, styles.css, demo.js, demo-data.js
   What it does: 5-question tap-only questionnaire for an HVAC job. The
   customer picks symptoms; the app returns a price range and an open
   appointment slot at the end.

02 OPERATIONS — public/demo/operations/
   Tab title: Client Portal - Operations Demo
   Files: index.html, styles.css, data.js, charts.js, app.js
   What it does: login -> role-based views. Internal dashboard with charts
   plus the client-facing portal, where onboarding steps tick off and the
   file advances on its own. Includes a "Reset demo data" control.

03 OUTBOUND — public/demo/outbound/
   Tab title: Client Win Back - Outbound Demo
   Files: index.html, styles.css, data.js, engine.js, app.js
   What it does: pulls dormant clients (no booking in 6+ months), ranks them
   by last spend, and matches each to a win-back offer. Flags clients who
   need re-consent before emailing (CASL).

DEPLOY NOTE: the SPA rewrite in vercel.json / _redirects sends unknown paths
to index.html. Static files under /demo/ are served before the rewrite
applies, so the demos load correctly — do not remove the trailing slash in
the demo URLs.

================================================================================
7. CONVENTIONS TO FOLLOW WHEN EDITING
================================================================================
- Colours: use tokens from theme.ts. Do not introduce a new hex without
  adding it to theme.ts and recording it in section 2 of this file.
- Copy: edit en.ts AND fr.ts. Never hardcode a string in a component.
- New homepage section: build it as its own component file, import it into
  Index.tsx in position, wrap blocks in <Reveal>, use the shared label/h2
  styles so the rhythm holds.
- Numbers in UI: tabular-nums.
- Demos are static and self-contained. Keep them dependency-free.
- Update section 8 with a dated entry for every change.
